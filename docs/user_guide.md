# User guide

## Run
Run everything from the project root (`module4-capstone`). See also `docs/deployment.md`.

1. Create and activate the virtual environment, then install dependencies:
```bash
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```
2. Start the triage service:
```bash
uvicorn services.triage.app:app --port 8080
```
3. Or run the whole end-to-end demo with one command (tests, eval, fixture check, RAG smoke, live API calls, perf):
```bash
bash scripts/demo.sh
```
4. Stop a background server if the port is busy:
```bash
kill $(lsof -ti :8080)
```

## Health check
```bash
curl localhost:8080/health
```
Expected: `{"service":"triage-api","version":"1.0.0","status":"healthy"}`

## Send a triage message
Log in as the coordinator, then send a message with the token:
```bash
TOKEN=$(curl -s -X POST localhost:8080/token -H "Content-Type: application/json" -d '{"username":"mercy","password":"logistics2026"}' | python -c "import sys,json;print(json.load(sys.stdin)['access_token'])")
curl -X POST localhost:8080/triage -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"patient_message":"child has chest pain","county":"Nairobi"}'
```
Expected: `urgency: high` with advice to seek emergency care. The demo credentials are for local teaching use only. Only the coordinator role can call `/triage`; the patient role gets a 403.

You can also try the endpoints interactively at `http://127.0.0.1:8080/docs`.

## Test commands
| Check | Command | Expected |
|---|---|---|
| Unit tests | `pytest -q` | all pass; integration test deselected |
| Integration test | `SERVICE_UP=1 pytest -o addopts="" -m integration` | pass (service must be running) |
| Golden-set eval | `python evals/run_eval.py evals/golden.jsonl` | `golden-set score: 3/3 = 1.00` |
| Fixture diagnosis | `python scripts/diagnose_fixture.py fixtures/triage_messages_sample.jsonl` | `diagnose OK, all rows agree with router` |
| RAG + MCP tool smoke | `python -m services.triage.rag_smoke` | `rag_smoke OK` |
| Perf stub | `python scripts/measure_perf.py --url http://localhost:8080/health --n 10 --out perf_stub.json` | writes `perf_stub.json` |

## Fallback path
The product runs in stub mode, so no live API key is needed:
- **Triage** uses a keyword model (`triage-stub-v1`) that flags urgent phrases such as chest pain or difficulty breathing as high urgency, and everything else as low.
- **RAG** retrieves from a small local document set by keyword overlap.
- **MCP logistics tool** reads clinic stock from the local `clinic.json`, with no network calls.
- The perf figure is a laptop teaching stub, not a production SLA.

If a live model is added later, it will be switched on by an environment variable in `.env`. Without it, the service stays in stub mode.
